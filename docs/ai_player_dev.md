## 機能1：AIプレイヤーとして1名参加

### 概要
大会発行時に、AIキャラクターを6人目のプレイヤーとして参加させるオプション。

### 仕様

#### 大会発行時
- 管理画面の大会発行UIにAIプレイヤーオプションを追加
- 選択可能キャラ：全9キャラ（下記「AIキャラ一覧」参照）
- AIキャラを選択すると、そのキャラのユーザーアカウントがDBに自動生成される

#### プレイヤー数・投票数
- 通常5名 → AIを加えて**6名**でゲームが進む
- 投票も6票になる（DB・ロジックの変更が必要）

#### AIの各フェーズ動作
| フェーズ | AIの動作 |
|---|---|
| ユーザー選択 | 自動で選択済み状態になる |
| 札作成 | 大会発行時に即時生成。札作成フェーズ開始と同時に完了済み扱い |
| 作品作成 | 手札選択・位置・前口上をAIが即時決定・投稿 |
| 投票 | AIが一番面白いと判断した作品に即時投票（自分の作品には投票不可ルール適用） |
| 連打ゲーム | 通常ユーザーの過去上位結果付近のランダム値を自動生成して送信 |

#### 待ち表示
- 完了済みステータスにAIの名前が表示される（例：「リナちゃん ✓」）
- ユーザーはAIが完了済みかどうか確認できる

#### 結果・アーカイブ
- 個人成績（PersonalStats）にはAIプレイヤーの分析・表示なし
- 過去結果（Archive・TournamentFinished）にはAIの作品・結果を含める

## 機能2：AI札作成モード

### 概要
大会発行時にAIが全員分（5名分）の札を生成するモード。ユーザーは自分で札を作らず、AIが生成した札を使ってゲームをプレイする。

### 仕様

#### 大会発行時
- 管理画面の大会発行UIに「AI札作成モード」オプションを追加
- 発行ボタンを押した瞬間にAPIを叩いてAIが全員分の札を生成
- 通常の「札作成フェーズ」はスキップ
- **ユーザー選択完了 → 即座にゲーム開始**（作品作成フェーズへ）

#### 生成ルール
- 枚数：発行時設定に準拠（例：各ユーザー分の枚数×5名分）
- 文字数：1〜20文字でバラエティ豊かに生成
  - 単語のみ
  - 短い文章
  - 前後に文字をくっつけると文章になるもの
  - 文字数が少ないもの〜長めのもの、混在させる
- 下ネタ枠あり（直接的な表現が難しい場合は間接的な表現でOK）
- 各ユーザーに割り当てた札として保存（creator_user_idが各ユーザーに設定される）

## 機能3：AIエキシビションモード

### 概要
個人AIキャラ5名（こんべ(AI)・スラパン(AI)・はじむ(AI)・カズさん(AI)・かっぴー(AI)）がゲームをプレイするモード。ユーザーは自分のAIの動きを確認しながら、ボタンを押して進行する。

### 固定設定
| 項目 | 設定値 |
|---|---|
| 回戦数 | 5回戦 |
| 各ユーザー札枚数 | 12枚（通常10枚 + 下ネタ2枚） |
| 投票モード | 通常とシークレットをランダム（なりすましはなし） |
| 決戦モード | 連打モード（連打のみ通常ユーザーが操作） |

### 大会発行
- 管理画面にエキシビションモード発行オプションを追加（ソロ・本番と同列に並べる）
- URLは通常大会と同じトークン形式（例：`/abc123def`）
- `/current` からアクセス可能
- **エキシビション中は本番大会の発行不可**（アクティブな大会があれば発行ブロックされる既存ロジックを流用）

### 結果・アーカイブ
- エキシビションの結果は通常の総合結果（summary・analytics）には**含まれない**
- エキシビション専用の過去結果タブをアーカイブに追加

### ユーザーフロー

#### ユーザー選択フェーズ
- 通常と同じ画面で各ユーザーが自分のアカウントを選択
- 全員選択完了後、AIが各キャラに割り当てられてゲーム開始

#### 札作成フェーズ
- AIが即時生成（AI札作成モードと同じロジック）
- ユーザーは操作不要（スキップ）

#### 作品作成フェーズ（各回戦）
- AIが手札・位置・前口上を決定し、入力済み状態で画面に表示
- **入力・選択項目はすべてdisabled（変更・編集不可）**
- ユーザーは内容を確認して「投稿」ボタンを押すだけ

#### 投票フェーズ（各回戦）
- AIが投票先を決定し、その作品が選択済み状態で表示
- **ユーザーは変更不可**
- 「投票する」ボタンを押すだけ

#### 連打決戦
- **連打のみ通常ユーザーが操作**（AIは参加しない）

### エキシビション中の結果
- エキシビション専用タブで過去結果を参照可能
- 通常のanalyticsやsummaryには反映されない

## 個人AIキャラのデータ設計

### 方針
- 各キャラの過去データ（作成した札・作品・前口上・投票した作品）をJSONファイルとして事前生成
- `data/ai_characters/` ディレクトリに配置
- Vercelはランタイムでのファイル書き込み不可だが読み込みはOK
- APIルートのサーバーサイドで `fs.readFile` して参照
- データ更新は手動（ユーザーがSQLを実行→JSON生成→コミット）

### JSONファイル配置
```
data/
  ai_characters/
    konbe.json
    surapan.json
    hajimu.json
    kazusan.json
    kappii.json
```

### JSONフォーマット
```json
{
  "userId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "userName": "こんべ",
  "createdCards": [
    "テキスト1",
    "テキスト2"
  ],
  "works": [
    {
      "topicText": "お題テキスト",
      "handText": "手札テキスト",
      "position": "before",
      "fullText": "手札テキストお題テキスト",
      "preamble": "前口上テキスト",
      "voteCount": 2
    }
  ],
  "votedWorks": [
    {
      "topicText": "お題テキスト",
      "handText": "手札テキスト",
      "position": "after",
      "fullText": "お題テキスト手札テキスト",
      "creatorName": "スラパン"
    }
  ]
}
```

### データ取得SQL（ユーザーが実行してJSONを生成する）

#### 作成した札
```sql
SELECT c.text
FROM cards c
JOIN users u ON c.creator_user_id = u.id
WHERE u.name = 'こんべ'
ORDER BY c.created_at;
```

#### 作品一覧（手札＋お題＋位置＋前口上＋得票数）
```sql
SELECT
  hc.text AS hand_text,
  tc.text AS topic_text,
  s.position,
  s.preamble,
  COUNT(v.submission_id) FILTER (WHERE v.is_tiebreaker = false) AS vote_count
FROM submissions s
JOIN users u ON s.user_id = u.id
JOIN cards hc ON s.hand_card_id = hc.id
JOIN games g ON s.game_id = g.id
JOIN cards tc ON g.topic_card_id = tc.id
LEFT JOIN votes v ON v.submission_id = s.id
WHERE u.name = 'こんべ'
GROUP BY s.id, hc.text, tc.text, s.position, s.preamble
ORDER BY g.created_at;
```

#### 投票した作品一覧
```sql
SELECT
  hc.text AS hand_text,
  tc.text AS topic_text,
  s.position,
  creator.name AS creator_name
FROM votes v
JOIN users voter ON v.voter_user_id = voter.id
JOIN submissions s ON v.submission_id = s.id
JOIN users creator ON s.user_id = creator.id
JOIN cards hc ON s.hand_card_id = hc.id
JOIN games g ON s.game_id = g.id
JOIN cards tc ON g.topic_card_id = tc.id
WHERE voter.name = 'こんべ'
  AND v.is_tiebreaker = false
ORDER BY v.created_at;
```

※ `こんべ` の部分を各ユーザー名に変えて5名分実行する

## AIモデル設定（src/lib/ai-config.ts）

AIコメント生成・AIプレイヤーのモデルは `src/lib/ai-config.ts` で管理しており、環境変数で切り替え可能。

### デフォルト値（環境変数未設定時）

| 用途 | デフォルトモデル | コスト感 |
|---|---|---|
| AIコメント生成（リナちゃん・大河内） | `claude-haiku-4-5-20251001` | ~$0.05/大会 |
| AIプレイヤー | `claude-sonnet-4-6` | ~$0.20〜0.35/大会 |

**環境変数を設定しなければデフォルト値が自動的に使われる。Vercelの環境変数に追加しなくても動作する。**

### 切り替え方法

**ローカル（.env.local）：**
```
AI_MODEL_COMMENTS=claude-sonnet-4-6
AI_MODEL_PLAYER=claude-haiku-4-5-20251001
```

**本番（Vercel）：**
Vercel ダッシュボード → Settings → Environment Variables に追加。
未設定のままにしておけばデフォルト値が使われる。

### 利用可能なモデル

| モデルID | 特徴 | コスト |
|---|---|---|
| `claude-haiku-4-5-20251001` | 高速・低コスト | 最安 |
| `claude-sonnet-4-6` | 高品質・複雑な指示に強い | Haikuの約3〜4倍 |
