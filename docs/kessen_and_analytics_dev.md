## 決戦時の新方法

### 概要
- 決戦投票のやり方をもう一つ追加したい
- これは決戦投票の方法をオプションで決めることができる
- 大会発行時に、オプションで、決選投票か連打ゲームか選べるようにする。管理画面に追加する
- 現在の決選投票は、決戦作者が除外されるため、決戦に進んだ作品の作者が、決戦作品に投稿していた場合、自動的に除外され、結果がわかってしまう感じがある。
- 全く別のゲームで決戦できるオプションを追加したい。

### 連打ゲーム仕様（決定済み）
- ３秒間でどれだけボタンを連打できるかを競うゲーム
- **2人は完全独立**してプレイする（リアルタイム同期不要）
  - それぞれが任意のタイミングで連打ゲームを実行
  - 連打回数が多い方が勝ち
- ボタンデザイン：画面中央に大きい丸いボタン（ゲームコントローラーのボタンイメージ）
- 1回目のボタン押下で3秒カウントダウン開始
- タップ回数はリアルタイムでカウント表示
- 3秒経過後に「終了」を表示し、結果をDBに保存
- **同点の場合：再戦（無制限、決着がつくまで）**
- 決戦に進んでいないユーザーには「現在決戦中！⚔️結果がでるまでお待ちください」を表示
- 結果画面：全員が見られる。各プレイヤーの連打回数と勝者を表示
- **+1票は廃止**（決戦勝利＝その回戦の1位として記録。票数の加算なし）

### DB変更
1. `tournaments` テーブルに `tiebreaker_mode` カラム追加
   - 型: `text`、デフォルト: `vote`
   - 値: `vote`（決選投票）| `button_mash`（連打ゲーム）
2. `games` テーブルの `status` に `waiting_button_mash` を追加
3. 新テーブル `button_mash_results` を作成
   - `id` uuid pk
   - `game_id` uuid fk → games
   - `user_id` text
   - `tap_count` int
   - `mash_round` int（同点再戦のラウンド番号、1始まり）
   - `completed_at` timestamptz

### フロー変更
- `waiting_vote` → 2作品同票検出時:
  - `tiebreaker_mode = vote` → `waiting_tiebreaker_vote`（既存）
  - `tiebreaker_mode = button_mash` → `waiting_button_mash`（新規）
- `waiting_button_mash` → 同点の場合 → `mash_round` をインクリメントして `waiting_button_mash` のまま継続
- `waiting_button_mash` → 決着 → `showing_result`

### 新規APIエンドポイント
- `POST /api/tournaments/[token]/button-mash`：連打結果を保存
- advance APIに `waiting_button_mash` ハンドラを追加

## データ分析について

### 概要
- 総合結果ページにデータ分析を追加
- 表示場所：大会終了後の総合結果ページのヘッダーに「総合結果」「個人成績」タブを追加し、タブ切り替えで表示
- 集計範囲：**全大会通算**（Supabase全データ）

### 個人成績の指標（決定済み）
1. **作成札採用率**：自分が作成した札が手札として作品に使われた回数 ÷ 作成した総カード枚数。野球の打率形式（.xxx）で表示
2. **ヒット数**：作品への得票数でヒット種別を分類
   - 1票 = シングルヒット（1B）
   - 2票 = ツーベース（2B）
   - 3票 = スリーベース（3B）
   - 4票以上 = ホームラン（HR）
3. **MVP回数**：その回戦で1位（最多票）になった回数
4. **投票的中率**：自分が投票した作品が最終的に勝者となった割合
5. **連打ゲーム勝率**：連打ゲームでの勝利数 ÷ 参加回数（連打ゲーム機能追加後）

※ 打席数（投稿数）は全員同じになるため除外

### ランキング表示
- 各指標で順位を表示
- 1位には 👑 を付与
- ユーザーはタブまたはアコーディオンで切り替えて個別閲覧可能

### 新規APIエンドポイント
- `GET /api/analytics`：全ユーザーの通算成績を集計して返す
